💲 Precios

costo + IVA = Lista 4 / (1 + factor L4)  ·  costo neto = (costo + IVA) / (1 + IVA)  ·   Lista n = round(costo neto × (1 + IVA) × factor Ln). El factor de la L4 se deriva solo (1 + inversa / 100).

📡 Modo de sync

/api/v1/sync (v1) no cambia nunca: las apps viejas siguen recibiendo exactamente el JSON actual. El modo solo decide qué responde el contrato nuevo. Inventario necesita el modo predeterminado para poder editar (si no, se ve pero no se modifica).

🔎 Parser de artículos

articleParser.js recorre las descripciones del inventario y separa fábrica, código, descripción y oferta de cada fila. Primero revisá el resultado y después aplicá las fábricas detectadas: solo completa las que están vacías, nunca pisa una fábrica ya cargada. Las filas sin marca detectada se completan con SIN FABRICA: ningún artículo queda sin fábrica.

📖 Guía de Configuración y Conexión a la API

Instrucciones para conectar apps, agentes de IA y servicios externos al backend de LOLA.

🌐 Direcciones Base (Base URL)

El backend de LOLA corre en Cloudflare Workers con base de datos SQLite serverless (Cloudflare D1):

  • Producción (HTTPS): https://lola-backend.elladecide.workers.dev
  • Desarrollo Local: http://localhost:8787
  • Emulador Android: http://10.0.2.2:8787 (mapeo directo a localhost del host)
🔑 Autenticación y Permisos

El modelo de acceso separa lecturas públicas de operaciones administrativas:

  • Lectura pública (sin token): /api/v1/version, /api/v1/sync, /api/v1/sync/v2, /api/v1/sync-config, /api/v1/parser-config, /api/v1/mapa-catalogo.
  • Escritura / Admin (requiere Bearer Token): POST /api/v1/admin/products, POST /api/v1/admin/rollback, DELETE /api/v1/admin/products/:codigo, etc.
  • Obtención del token: Realizá un POST /api/v1/auth/login con JSON {"username": "...", "password": "..."}. La respuesta entrega un JWT con validez de 24 horas.
🔄 Protocolo de Sincronización (Offline-First por Hash)

Para máxima eficiencia de red y rendimiento en dispositivos móviles y agentes:

  1. Consultar versión: Llamar periódicamente o al abrir la app a GET /api/v1/version. Responde { "revision": N, "hash": "..." }.
  2. Comparar hash local: Si el hash recibido es idéntico al guardado en la base local, el catálogo está 100% al día. No se hace ninguna petición más.
  3. Descarga completa o delta: Si el hash cambió, llamar a GET /api/v1/sync/v2 para refrescar la base de datos local.
📡 Endpoints Principales y Parámetros
Endpoint Método / Auth Descripción y Parámetros
/api/v1/version GET · Libre Devuelve { revision, hash, updated_at } para chequeo instantáneo.
/api/v1/sync/v2 GET · Libre Contrato moderno completo. Parámetros opcionales:
• ?since=YYYY-MM-DD HH:MM:SS (cambios desde fecha UTC)
• ?page=N&limit=M (paginación ordenada por código)
• ?fields=col1,col2 (proyección de campos específicos)
/api/v1/sync GET · Libre Contrato v1 aditivo e inmutable para clientes clásicos de teclado.
/api/v1/admin/products POST · Bearer Upsert parcial (replace: false) o reemplazo total atómico con rotación de backups (replace: true).
/api/v1/admin/rollback POST · Bearer Restaura inmediatamente el catálogo anterior desde bak o bak2.
🏷️ Estructura del Producto y Listas

Cada artículo del catálogo contiene:

  • codigo_unico: Identificador primario determinístico (ej: "KAUR8146").
  • descripcion: Nombre comercial completo del artículo.
  • precios: Array de 4 enteros [Lista 1, Lista 2, Lista 3, Lista 4]. La Lista 4 es el precio base de catálogo.
  • costo_neto y costo_iva: Valores de costo sin/con IVA.
  • oferta: Booleano. Si es true, las 4 listas vienen igualadas al valor de liquidación.
  • fabrica, codigo (modelo de fábrica), categoria y stock.
⚠️ Observaciones y Detalles Técnicos
  • CORS Universal: Encabezado Access-Control-Allow-Origin: * activo en todas las rutas para consumo directo desde navegadores y paneles web.
  • Sin caché de navegador: Todas las respuestas dinámicas devuelven Cache-Control: no-store para asegurar consistencia inmediata.
  • Horarios en UTC: Todos los campos temporales (updated_at, serverTime) se generan y comparan en hora UTC (formato YYYY-MM-DD HH:MM:SS).
  • Rotación Segura: Al hacer reemplazo total, D1 rota automáticamente la versión anterior a la tabla de backup más vieja (products_bak o products_bak2), garantizando reversión con 1 click.
