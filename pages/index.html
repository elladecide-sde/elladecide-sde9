📖 Guía de Configuración y Conexión a la API

Instrucciones para conectar apps, agentes de IA y servicios externos al backend de LOLA.

🌐 Direcciones Base (Base URL)

El backend de LOLA corre en Cloudflare Workers con base de datos SQLite serverless (Cloudflare D1):

  • Producción (HTTPS): https://lola-backend.elladecide.workers.dev
  • Desarrollo Local: http://localhost:8787
  • Emulador Android: http://10.0.2.2:8787 (mapeo directo a localhost del host)
🔑 Autenticación y Permisos

El modelo de acceso separa lecturas públicas, acceso de clientes y operaciones administrativas:

  • Lectura pública de catálogo (sin token): /api/v1/version, /api/v1/sync, /api/v1/sync/v2, /api/v1/sync-config, /api/v1/parser-config, /api/v1/mapa-catalogo.
  • Clientes de Ella (comprasED v2): Envía Authorization: Bearer <Firebase_ID_Token>. El Worker valida la firma contra Google, resuelve automáticamente el DNI vía Firestore REST (users/{uid}.dni) y restringe el acceso estrictamente a sus propios comprobantes.
  • Escritura / Admin / Sync-Agent: Requiere encabezado x-api-key: <COMPRAS_API_KEY> o Authorization: Bearer <LOLA_Admin_JWT> para operaciones de catálogo (POST /api/v1/admin/products, POST /api/v1/admin/rollback) o administración de compras (POST /api/v1/compras/consulta, POST /api/v1/compras/reset, etc.).
  • Obtención del token administrativo: Realizá un POST /api/v1/auth/login con JSON {"username": "...", "password": "..."}. La respuesta entrega un JWT con validez de 24 horas.
🔄 Protocolo de Sincronización (Offline-First por Hash)

Para máxima eficiencia de red y rendimiento en dispositivos móviles y agentes:

  1. Consultar versión: Llamar periódicamente o al abrir la app a GET /api/v1/version. Responde { "revision": N, "hash": "..." }.
  2. Comparar hash local: Si el hash recibido es idéntico al guardado en la base local, el catálogo está 100% al día. No se hace ninguna petición más.
  3. Descarga completa o delta: Si el hash cambió, llamar a GET /api/v1/sync/v2 para refrescar la base de datos local.
📡 Endpoints Principales y Parámetros
Endpoint Método / Auth Descripción y Parámetros
/api/v1/version GET · Libre Devuelve { revision, hash, updated_at } para chequeo instantáneo del catálogo.
/api/v1/sync/v2 GET · Libre Contrato moderno completo. Parámetros opcionales:
• ?since=YYYY-MM-DD HH:MM:SS (cambios desde fecha UTC)
• ?page=N&limit=M (paginación ordenada por código)
• ?fields=col1,col2 (proyección de campos específicos)
/api/v1/sync GET · Libre Contrato v1 aditivo e inmutable para clientes clásicos de teclado.
/api/v1/compras/resumen GET · Firebase / Key Resumen liviano del cliente. Soporta If-None-Match: W/"<hash>" para responder 304 Not Modified (0 bytes).
Devuelve { pendientes, procesados, estado_sync, existe_en_mdb, hash, updated_at }.
/api/v1/comprasED GET · Firebase / Key Comprobantes enriquecidos. Parámetros:
• ?estado=DISPONIBLE|PROCESADO|ANULADO
• ?since=ISO_UTC · ?limit=50 · ?cursor=id_doc
/api/v1/compras/ack POST · Firebase / Key Confirmación 100% idempotente de lectura. Recibe {"ids_documentos": [...]} y devuelve confirmados, ya procesados y no encontrados.
/api/v1/compras/interesados POST/GET · Firebase / Key Registra DNIs en cola de sincronización con rango ("48h", "7d", "1m", "personalizada") y consulta estado operativo.
/api/v1/compras/consulta POST · Key Admin Consulta administrativa en lote para múltiples DNIs en una sola llamada.
/api/v1/admin/products POST · Bearer Admin Upsert parcial (replace: false) o reemplazo total atómico con rotación de backups (replace: true).
/api/v1/admin/rollback POST · Bearer Admin Restaura inmediatamente el catálogo anterior desde bak o bak2.
🏷️ Estructura del Producto y Listas

Cada artículo del catálogo contiene:

  • codigo_unico: Identificador primario determinístico (ej: "KAUR8146").
  • descripcion: Nombre comercial completo del artículo.
  • precios: Array de 4 enteros [Lista 1, Lista 2, Lista 3, Lista 4]. La Lista 4 es el precio base de catálogo.
  • costo_neto y costo_iva: Valores de costo sin/con IVA.
  • oferta: Booleano. Si es true, las 4 listas vienen igualadas al valor de liquidación.
  • fabrica, codigo (modelo de fábrica), categoria y stock.
🛍️ Módulo comprasED v2 (Historial de Compras y Targeted Sync)

Sincronización bajo demanda y consulta de historial de compras por cliente para la plataforma de Ella:

  • Autenticación Dual: • App de Ella: Enviar Authorization: Bearer <Firebase_ID_Token>. El Worker resuelve el DNI vía Firestore REST (users/{uid}.dni) con aislamiento estricto (no hace falta enviar ?dni=).
    • Panel / Admin: Enviar x-api-key: <COMPRAS_API_KEY>.
  • 1. Resumen Liviano con ETag (GET /api/v1/compras/resumen): Consultar con encabezado If-None-Match: W/"<hash>". Si nada cambió, responde 304 Not Modified sin cuerpo. Informa pendientes, procesados, ultimo_id_documento y estado_sync (PENDIENTE_SYNC, CLIENTE_NO_ENCONTRADO, SIN_COMPRAS, CON_COMPRAS).
  • 2. Descarga de Compras (GET /api/v1/comprasED): Filtro por ?estado=DISPONIBLE, ?since=ISO_UTC y paginación con ?limit=50 y ?cursor=id_doc. Comprobantes enriquecidos con numero_comprobante, cliente, localidad, sucursal, descuento, forma_pago, anulado, nota_credito_de, y artículos con fabrica, codigo, iva y descuento.
  • 3. Confirmación Idempotente / ACK (POST /api/v1/compras/ack): Envía {"ids_documentos": [189130]} para marcar como PROCESADO. Es 100% idempotente y detalla confirmados, ya_procesados y no_encontrados.
  • 4. Registro de Clientes (POST /api/v1/compras/interesados): Auto-registro desde app con {"rango": "48h"} o registro en lote con {"dnis": ["32685684"], "rango": "48h"}. Rangos: "48h", "7d", "1m" o "personalizada" con desde y hasta.
  • 5. Webhook Push Opcional: Configurando ELLA_WEBHOOK_URL y ELLA_WEBHOOK_SECRET, LOLA notifica vía POST con firma HMAC-SHA256 (x-lola-signature) ante compras nuevas.
⚠️ Observaciones y Detalles Técnicos
  • CORS Universal: Encabezado Access-Control-Allow-Origin: * activo en todas las rutas para consumo directo desde navegadores y paneles web.
  • Sin caché de navegador: Todas las respuestas dinámicas devuelven Cache-Control: no-store para asegurar consistencia inmediata.
  • Horarios en UTC: Todos los campos temporales (updated_at, serverTime) se generan y comparan en hora UTC (formato YYYY-MM-DD HH:MM:SS).
  • Rotación Segura: Al hacer reemplazo total, D1 rota automáticamente la versión anterior a la tabla de backup más vieja (products_bak o products_bak2), garantizando reversión con 1 click.
